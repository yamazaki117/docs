# Integrating with Visare for Cl@ve

This guide will walk you through the process of integrating your application with the Visare OAuth2 implementation for Cl@ve authentication.

## Quickstart

Integrating with Visare requires just a few steps to add Cl@ve authentication to your application.

<Steps>
  <Step title="Register Your Application">
    Create a developer account at the [Visare Developer Portal](https://developer.visare.es) and register your application to receive your client credentials.
    
    You'll need to provide:
    - Application name
    - Redirect URI(s)
    - Brief description of your application
  </Step>
  
  <Step title="Implement the Authorization Code Flow with PKCE">
    For security reasons, Visare only supports the Authorization Code Flow with PKCE. Below are implementation examples.
    
    <CodeGroup>
      ```javascript JavaScript
      // 1. Generate a Code Verifier and Challenge
      function generateCodeVerifier(length) {
        let text = '';
        const possible = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-._~';
        for (let i = 0; i < length; i++) {
          text += possible.charAt(Math.floor(Math.random() * possible.length));
        }
        return text;
      }
      
      async function generateCodeChallenge(codeVerifier) {
        const encoder = new TextEncoder();
        const data = encoder.encode(codeVerifier);
        const digest = await window.crypto.subtle.digest('SHA-256', data);
        
        return btoa(String.fromCharCode(...new Uint8Array(digest)))
          .replace(/\+/g, '-')
          .replace(/\//g, '_')
          .replace(/=/g, '');
      }
      
      // Generate and store values
      const codeVerifier = generateCodeVerifier(128);
      const codeChallenge = await generateCodeChallenge(codeVerifier);
      sessionStorage.setItem('codeVerifier', codeVerifier);
      
      // 2. Redirect user to authorization endpoint
      function redirectToAuth() {
        const clientId = 'YOUR_CLIENT_ID';
        const redirectUri = encodeURIComponent('YOUR_REDIRECT_URI');
        const state = generateRandomState();
        sessionStorage.setItem('state', state);
        
        // Available scopes include:
        // - openid: Required base scope for OIDC
        // - profile: Basic profile information (name, gender, birthdate)
        // - email: User's email address
        // - document: ID document information (DNI/NIE number)
        // - address: User's registered address information
        // - phone: User's telephone number
        const scope = 'openid profile email';
        
        window.location.href = `https://auth.visare.es/authorize?` +
          `client_id=${clientId}&` +
          `response_type=code&` +
          `redirect_uri=${redirectUri}&` +
          `scope=${encodeURIComponent(scope)}&` +
          `code_challenge=${codeChallenge}&` +
          `code_challenge_method=S256&` +
          `state=${state}`;
      }
      ```
      
      ```python Python
      import secrets
      import hashlib
      import base64
      import requests
      
      # 1. Generate a Code Verifier and Challenge
      def generate_code_verifier(length=128):
          return secrets.token_urlsafe(length)
          
      def generate_code_challenge(verifier):
          digest = hashlib.sha256(verifier.encode('utf-8')).digest()
          return base64.urlsafe_b64encode(digest).decode('utf-8').rstrip('=')
          
      # Generate and store values
      code_verifier = generate_code_verifier()
      code_challenge = generate_code_challenge(code_verifier)
      
      # 2. Create authorization URL
      def get_authorization_url():
          client_id = 'YOUR_CLIENT_ID'
          redirect_uri = 'YOUR_REDIRECT_URI'
          state = secrets.token_urlsafe(16)
          
          # Available scopes:
          # - openid: Required base scope for OIDC
          # - profile: Basic profile information (name, gender, birthdate)
          # - email: User's email address
          # - document: ID document information (DNI/NIE number)
          # - address: User's registered address information
          # - phone: User's telephone number
          scope = 'openid profile email'
          
          params = {
              'client_id': client_id,
              'response_type': 'code',
              'redirect_uri': redirect_uri,
              'scope': scope,
              'code_challenge': code_challenge,
              'code_challenge_method': 'S256',
              'state': state
          }
          
          auth_url = 'https://auth.visare.es/authorize'
          return auth_url, params, code_verifier, state
      ```

      ```python Python
      # Handle callback
      def exchange_code_for_tokens(code, code_verifier, redirect_uri):
      ```

## Authentication Flow Explained

Visare implements the Authorization Code Flow with PKCE (Proof Key for Code Exchange), which is the most secure OAuth2 flow and works for all application types.

### Authorization Request Parameters

When redirecting users to the authorization endpoint, you'll need to include these parameters:

| Parameter | Required | Description |
|-----------|----------|-------------|
| `client_id` | Yes | Your application's client ID obtained during registration |
| `response_type` | Yes | Must be set to `code` for the authorization code flow |
| `redirect_uri` | Yes | The URI where the user will be redirected after authentication (must match one of your registered URIs) |
| `scope` | Yes | Space-separated list of permissions your app is requesting |
| `code_challenge` | Yes | The SHA-256 hash of your code verifier, base64url-encoded |
| `code_challenge_method` | Yes | Must be set to `S256` to indicate SHA-256 hashing |
| `state` | Yes | A random string to prevent CSRF attacks, should be verified when handling the callback |
| `login_hint` | No | Pre-fills the user's identification (e.g., DNI/NIE) |
| `ui_locales` | No | Preferred languages for the UI, comma-separated (e.g., `es,ca,en`) |

The flow works as follows:

1. **Your application** generates a code verifier and its derived code challenge
2. **Your application** redirects the user to Visare's authorization endpoint with the code challenge
3. **Visare** redirects the user to **Cl@ve** where they authenticate using their Spanish digital identity
4. After successful authentication, **Cl@ve** redirects back to **Visare**
5. **Visare** redirects to your application with an authorization code
6. **Your application** exchanges this code and the original code verifier for tokens
7. **Your application** can now use the access token to retrieve user information

This flow ensures that even if the authorization code is intercepted, it cannot be used without the code verifier that only your application possesses.

## Available Endpoints

| Endpoint | URL | Purpose |
|----------|-----|---------|
| Authorization | `https://auth.visare.es/authorize` | Initiates the authentication process |
| Token | `https://auth.visare.es/token` | Exchanges authorization code for tokens |
| User Info | `https://api.visare.es/userinfo` | Retrieves authenticated user information |
| Token Revocation | `https://auth.visare.es/revoke` | Revokes an access or refresh token |

## User Information

The userinfo endpoint returns information about the authenticated user based on the scopes requested:


## Testing Environment

Visare provides a sandbox environment for testing your integration:

```
Authorization Endpoint: https://sandbox.auth.visare.es/authorize
Token Endpoint: https://sandbox.auth.visare.es/token
User Info Endpoint: https://sandbox.api.visare.es/userinfo
```

The sandbox environment allows you to test your integration without connecting to the actual Cl@ve system. Key features include:

- **Simulated Verifications**: The sandbox simulates the Cl@ve verification process
- **Test Controls**: You can simulate both approval and rejection scenarios
- **Test Tokens**: Upon successful authentication, you'll receive test tokens
- **Mock Data**: When using these sandbox tokens with the userinfo endpoint, you'll receive predictable test data for each requested scope

### Sandbox Test Data

The sandbox returns different test data based on the scopes you request:

| Scope | Sample Data Returned |
|-------|----------------------|
| profile | `{"name": "Test User", "given_name": "Test", "family_name": "User", "birthdate": "1980-01-01", "gender": "not specified"}` |
| email | `{"email": "test.user@example.com", "email_verified": true}` |
| document | `{"document_type": "DNI", "document_number": "12345678Z"}` |
| address | `{"address": {"street_address": "Calle Test 123", "locality": "Madrid", "region": "Madrid", "postal_code": "28001", "country": "ES"}}` |
| phone | `{"phone_number": "+34600000000", "phone_number_verified": true}` |

### Testing Rejection Scenarios

To simulate a rejection scenario in the sandbox, add the `test_scenario=rejection` parameter to your authorization request:

```javascript
window.location.href = `https://sandbox.auth.visare.es/authorize?` +
  // other parameters... +
  `test_scenario=rejection`;
```

## Security Best Practices

<Accordion title="Always Validate Tokens">
  Always validate tokens received from Visare to ensure they are legitimate and haven't been tampered with.
</Accordion>

<Accordion title="Store Tokens Securely">
  Store tokens securely and never expose them in client-side code. For web applications, consider using HttpOnly cookies.
</Accordion>

<Accordion title="Implement Proper CSRF Protection">
  Always use the state parameter to prevent cross-site request forgery attacks.
</Accordion>

<Accordion title="Use Short-lived Access Tokens">
  Configure your client to request short-lived access tokens and use refresh tokens to get new ones when needed.
</Accordion>
