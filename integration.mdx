# Integrating with Visare for Cl@ve

This guide provides the essential information for integrating your application with Visare's OAuth2 implementation for Cl@ve.

## Quickstart

<Steps>
  <Step title="Register Your Application">
    Create a developer account at the [Visare Developer Portal](https://developer.visare.es) and register your application to receive your client credentials.
    
    You'll need to provide:
    - Application name
    - Redirect URI(s)
    - Brief description of your application
  </Step>
  
  <Step title="Choose an OAuth Library">
    Visare implements the standard Authorization Code Flow with PKCE. You can use any OAuth2 library that supports this flow.
    
    Popular libraries include:
    - **JavaScript**: [auth0-spa-js](https://github.com/auth0/auth0-spa-js), [oidc-client-js](https://github.com/IdentityModel/oidc-client-js)
    - **Python**: [Authlib](https://authlib.org/), [requests-oauthlib](https://github.com/requests/requests-oauthlib)
    - **Java**: [Spring Security OAuth](https://spring.io/projects/spring-security-oauth)
    - **PHP**: [league/oauth2-client](https://github.com/thephpleague/oauth2-client)
    - **.NET**: [Microsoft.Identity.Web](https://github.com/AzureAD/microsoft-identity-web)
  </Step>
  
  <Step title="Configure Your OAuth Client">
    Configure your OAuth client using Visare's endpoints:
    
    **Production Environment:**
    ```
    Authorization Endpoint: https://auth.visare.es/authorize
    Token Endpoint: https://auth.visare.es/token
    User Info Endpoint: https://api.visare.es/userinfo
    Token Revocation Endpoint: https://auth.visare.es/revoke
    ```
    
    **Sandbox Environment:**
    ```
    Authorization Endpoint: https://sandbox.auth.visare.es/authorize
    Token Endpoint: https://sandbox.auth.visare.es/token
    User Info Endpoint: https://sandbox.api.visare.es/userinfo
    Token Revocation Endpoint: https://sandbox.auth.visare.es/revoke
    ```
  </Step>
</Steps>

## Visare-Specific Requirements

When integrating with Visare, keep these requirements in mind:

<CardGroup cols={2}>
  <Card title="PKCE Required" icon="shield-check">
    Visare **requires** PKCE for all OAuth2 flows, even for server-side applications, for maximum security.
  </Card>
  <Card title="TLS 1.2+" icon="lock">
    All requests to Visare endpoints must use TLS 1.2 or higher.
  </Card>
  <Card title="State Parameter" icon="random">
    The `state` parameter must be used in authorization requests to prevent CSRF attacks.
  </Card>
  <Card title="Redirect URIs" icon="arrow-right">
    Redirect URIs must match exactly (including trailing slashes) with those registered in the developer portal.
  </Card>
</CardGroup>

## Available Scopes

Visare offers the following scopes, corresponding to identity information available from Cl@ve:

| Scope | Description | Sample Data |
|-------|-------------|-------------|
| `openid` | **Required** base scope for OIDC | `{"sub": "12345678Z"}` |
| `profile` | Basic profile information | `{"name": "María García", "given_name": "María", "family_name": "García", "birthdate": "1980-01-01", "gender": "female"}` |
| `email` | Email address | `{"email": "maria.garcia@example.com", "email_verified": true}` |
| `document` | ID document information | `{"document_type": "DNI", "document_number": "12345678Z"}` |
| `address` | Registered address | `{"address": {"street_address": "Calle Gran Vía 123", "locality": "Madrid", "region": "Madrid", "postal_code": "28013", "country": "ES"}}` |
| `phone` | Phone number | `{"phone_number": "+34600000000", "phone_number_verified": true}` |

## Authorization Parameters

In addition to standard OAuth2 parameters, Visare supports these optional parameters:

| Parameter | Description |
|-----------|-------------|
| `login_hint` | Pre-fills the user's DNI/NIE during authentication |
| `ui_locales` | Sets the preferred UI language (`es`, `ca`, `gl`, `eu`, or `en`) |
| `acr_values` | Authentication level requested (`loa:basic` or `loa:substantial`) |

Example:
```
https://auth.visare.es/authorize?
  client_id=YOUR_CLIENT_ID&
  response_type=code&
  ...
  &login_hint=12345678Z
  &ui_locales=es
  &acr_values=loa:substantial
```

## Sandbox Testing

The sandbox environment simulates Cl@ve verification for testing purposes.

### Test Controls

You can control the sandbox behavior using the `test_scenario` parameter:

| Test Scenario | Description |
|---------------|-------------|
| `approval` | Simulates a successful authentication (default) |
| `rejection` | Simulates user rejection of authentication |
| `expired_session` | Simulates a session timeout during authentication |

Example:
```
https://sandbox.auth.visare.es/authorize?
  client_id=YOUR_CLIENT_ID&
  ...
  &test_scenario=rejection
```

### Test Data

When using the sandbox userinfo endpoint with obtained test tokens, you'll receive consistent mock data based on your requested scopes.

## Error Responses

Visare follows standard OAuth2 error responses. Common errors include:

| Error Code | Description |
|------------|-------------|
| `invalid_request` | Missing required parameter or malformed request |
| `unauthorized_client` | Client not authorized to use the requested flow |
| `access_denied` | User denied the authentication request |
| `invalid_scope` | Requested scope is invalid or unsupported |
| `server_error` | Unexpected error on the server |

Example error response:
```json
{
  "error": "invalid_grant",
  "error_description": "Authorization code expired"
}
```

## Sample Integration

<Accordion title="Simple Web Integration with auth0-spa-js">
```javascript
import createAuth0Client from '@auth0/auth0-spa-js';

const auth0 = await createAuth0Client({
  domain: 'auth.visare.es',
  client_id: 'YOUR_CLIENT_ID',
  redirect_uri: window.location.origin + '/callback',
  audience: 'https://api.visare.es',
  scope: 'openid profile email document',
  useRefreshTokens: true
});

// Login with redirect
const login = async () => {
  await auth0.loginWithRedirect();
};

// Handle callback
const handleCallback = async () => {
  await auth0.handleRedirectCallback();
  const user = await auth0.getUser();
  console.log(user);
};
```
</Accordion>

<Accordion title="Express Backend Integration with Passport.js">
```javascript
const passport = require('passport');
const { Strategy } = require('passport-oauth2');
const express = require('express');
const app = express();

// Configure OAuth strategy
passport.use(new Strategy({
  authorizationURL: 'https://auth.visare.es/authorize',
  tokenURL: 'https://auth.visare.es/token',
  clientID: 'YOUR_CLIENT_ID',
  clientSecret: 'YOUR_CLIENT_SECRET',
  callbackURL: 'https://your-app.com/callback',
  scope: ['openid', 'profile', 'email'],
  pkce: true, // Ensure PKCE is enabled
  state: true // Enable state parameter for CSRF protection
}, (accessToken, refreshToken, profile, done) => {
  // Fetch user info
  fetch('https://api.visare.es/userinfo', {
    headers: { 'Authorization': `Bearer ${accessToken}` }
  })
    .then(res => res.json())
    .then(userInfo => {
      return done(null, userInfo);
    })
    .catch(err => done(err));
}));

// Auth routes
app.get('/login', passport.authenticate('oauth2'));
app.get('/callback', passport.authenticate('oauth2', {
  successRedirect: '/profile',
  failureRedirect: '/login'
}));
```
</Accordion>
